## 一、设备背景（写补丁前必须先懂的现场约束）

1. **输出模式四态**（`output_mode()` 读 `OUTP:TRAC/SERI/PARA?`）：NORM 三路独立 /
   TRAC 跟踪（CH2 跟随 CH1 输出**同等值负电压**）/ SERI 串联 / PARA 并联。
   三模式由**继电器**实现，切换有硬件风险 → `_set_mode_cmd()` 里 `if any(self.get_output_state()): raise`
   是无条件的（`dh1766.py:347-348`），不依赖 `safe_mode`。这条设计是对的，改别处时别动它。
2. **本机长期挂在 TRAC、带电**（2026-09-13 留痕 `TEST_DATA/dh1766/psu_lock_probe_*.json`）：
   CH1/CH2 = ±12 V、CH1 ≈0.39 A 带载。**CH2 的 −11.99 V 是跟踪跟随，不是故障**。
3. **任何远程会话都会把设备置为 REM**（实测 V0.1.4.3）：新建会话第一条 `SYST:COMM:RLST?`
   就返回 `REM`；发 `SYST:LOC` 立即回 `LOC`（只交还面板控制权，**不影响输出/电压/模式**）。
   MCP 的电源工具已在收尾自动补发（`server.py::_psu_close`），库侧 `local()` 是显式方法。
   > 注意：手册写的 `SYST:COMM:RLST:STAT?` 在本机**无响应（超时）**，可用写法是
   > `SYST:COMM:RLST?`；速查表第 27 行已更正。
4. **指令间隔**（手册 4.1）：普通命令 ≥100 ms、切通道 ≥300 ms、串并联继电器 ≥500 ms；
   库内 `CMD_DELAY_S/CHANNEL_SWITCH_DELAY_S/RELAY_DELAY_S` 对应这三档。补丁不要省 sleep。
5. **MCP 侧现役门**（改库时别破坏）：`psu_output(ch,on,expect_mode,confirm)`、
   `psu_power_cycle(...,confirm)` 的 `confirm` 是"已获关断授权"的声明；
   `expect_mode` 只校验不设置（`_check_mode` fail-closed，空声明也会被拒）。

## 二、缺陷详述

### H1【高】`safe_mode` 被 `apply_*` 旁路 —— 带电通道的设定能被一句话改掉

**现象**：`safe_mode=True` 的设计语义是"接负载时不许改带电通道的设定"
（类 docstring `dh1766.py:13-15`）。单通道 setter 都执行这个检查：

```python
# dh1766.py:186 / 210 / 255 / 276 —— set_voltage / set_ovp / set_current / set_ocp 都调了
self._guard_set(ch)
```
```python
# dh1766.py:641-651
def _guard_set(self, ch: Channel) -> None:
    if not self.safe_mode:
        return
    states = self.get_output_state()
    if states[n - 1]:
        raise RuntimeError(f"safe_mode: CH{n} 输出开启中，拒绝修改设定；请先 set_output(...)")
```

而**一次写全部三路**的复合命令没有这个守卫：

```python
# dh1766.py:560-572
def apply_voltage(self, values: Optional[list[float]] = None) -> Optional[list[float]]:
    ...
    if len(values) != 3:
        raise ValueError("values must have exactly 3 elements")
    self.client.write(f"{C.APPL_VOLT} {values[0]},{values[1]},{values[2]}")   # ← 无 _guard_set
    time.sleep(CMD_DELAY_S)
    return self.apply_voltage()          # 回读会如实返回**已变**的设定值
```
`apply_current()`（`dh1766.py:574-584`）同形同问题。

**影响**：`safe_mode` 是本库**唯一**写保护。`apply_voltage([5.0, 0, 0])` 可以在 CH1 正
带载输出 12 V 时把它改成 5 V——被测板立刻掉压。而且它"看起来是安全的"：有回读、有长度校验、
函数名也不像危险操作。

**触发序列**（真机复现用）：
```python
ps = DH1766(VisaClient(res), safe_mode=True)
ps.get_output_state()                 # 例：[True, False, False]（CH1 带电）
ps.apply_voltage([5.0, 0.0, 0.0])     # 期望被拒；当前实现会真的写下去
```

**建议补丁**（离线可写、真机才需验）：
```python
def apply_voltage(self, values=None):
    if values is None:
        ...查询分支不变...
    if len(values) != 3:
        raise ValueError("values must have exactly 3 elements")
    if self.safe_mode:
        # 只对被改动的通道做守卫：三路全 equal 时不算改动（幂等调用不该被拒）
        cur = self.apply_voltage()
        for i, (new, old) in enumerate(zip(values, cur), start=1):
            if abs(float(new) - float(old)) > 1e-9:
                self._guard_set(i)          # 带电通道 → 直接 RuntimeError
    self.client.write(...)
```
同样处理 `apply_current`。**不要**简单地在 `safe_mode` 下一律拒绝——那会让
`snapshot`/巡检类脚本在 safe_mode 下连"无改动写"都做不了（本仓已有脚本这么用）。

**验收**：§五 的真机清单 T3。离线可断言的部分：给 `_guard_set` 打桩（monkeypatch），
断言"改动通道必被调用、幂等调用不被调用"。

### H2【高】`rst()` 裸暴露 `*RST`

```python
# dh1766.py:617-626（节选）
def rst(self) -> None:
    """...*RST 复位（恢复出厂设定）..."""
    self.client.write(C.RST)
```
AGENTS.md §二 明确：`*RST` 属复位类命令，"需用户显式授权（dh1766 用 `--allow-rst` 模式）"。
MCP 通用写口已拦（黑名单 `forbidden`），但**库层方法本身没有门**——任何脚本 `ps.rst()`
一行即可清掉现场设定（出厂 32/32/6 V、3 A/3 A/3 A，且 EXPERIENCE.md §3 记录其有 ~3 s 软复位过程）。

**建议补丁**：照 `sds_control.sds.shutdown(confirm=True)` 的既有范式加门：

```python
def rst(self, confirm: bool = False) -> None:
    if not confirm:
        raise RuntimeError("rst 需要 confirm=True（*RST 会清空全部设定，仅显式授权场景使用）")
    self.client.write(C.RST)
```
**验收**：离线断言 `confirm=False` 抛错且**未发命令**（用 fake client 记录写调用）；
真机阶段（可选）用 `--allow-rst` 脚本显式跑一次并留痕。

### M1【中】`remote()` / `rwlock()` 仍在库层暴露

```python
# dh1766.py:83-91
def remote(self) -> None:  """SYST:REM 远程模式（外控）。"""     self.client.write(C.SYST_REM)
def rwlock(self) -> None:  """SYST:RWL 远程锁定（面板 Lock 键不可切回本地…）""" self.client.write(C.SYST_RWL)
```
AGENTS.md 明令：禁止远程锁定类命令（`SYST:RWL` 会让面板 Lock 键无法切回本地，
需 `SYST:LOC` 才能恢复）。MCP 通用写口已拦，但库层方法还在，且
`TEST_SCRIPTS/dh1766/test_dh1766_full.py:218` **已经在直呼 `ps.remote()`**——
也就是说"面板保护"在脚本路径上是失效的。

**建议**：二选一——① 删除 `rwlock()`（没有正当自动化用途），`remote()` 加
`allow_remote_lock: bool = False` 显式门；② 保留但把 docstring 改成"**禁止在共享
实验台上调用**"，并在脚本侧清理直呼点（把 test_dh1766_full 的 `remote()` 段改为
`--allow-remote` 门控）。
**验收**：离线断言门生效；`grep -rn "\.remote()\|\.rwlock()"` 全仓零裸调用。

### M2【中】`set_output()` 写后不回读、不查错

```python
# dh1766.py:303-312
def set_output(self, ch, state, expect_mode) -> None:
    self._check_mode(expect_mode)          # 只校验模式（拓扑门，正确）
    self.select_channel(ch)
    self.client.write(f"{C.OUTP} {'ON' if state else 'OFF'}")   # ← 无 SYST:ERR?、无回读
    time.sleep(CMD_DELAY_S)
```
对照同库 `set_output_all()`（`319-334`）：循环写完会 `get_output_state()` 回读比对，
不一致直接抛 `RuntimeError`；`set_output_mode()`（`389-407`）也验证了。也就是说：
**三路一起开有验证，单路开没有**。MCP 层 `psu_output` 靠外层的回读补上了这一点
（`server.py::psu_output` 里 `{"output_on": p.get_output_state(), ...}`），但库被脚本
直接调用时，"被拒（例如 -200）"会表现得像成功。

**建议补丁**（对齐 AGENTS.md 铁律 3：写入 → 查 `SYST:ERR?` → 回读比对）：
```python
    self.client.write(f"{C.OUTP} {'ON' if state else 'OFF'}")
    time.sleep(CMD_DELAY_S)
    err = self.system_error()
    if err and not err.startswith("0"):
        raise RuntimeError(f"OUTP 写入被拒: {err}")
    got = self.get_output_state()[_ch_num(ch) - 1]
    if got != bool(state):
        raise RuntimeError(f"OUTP 回读不一致：期望 {bool(state)}，实得 {got}")
```
**验收**：真机清单 T2（正常路径 + 故意构造被拒的路径）。离线：fake client 返回
"被拒错误串/相反状态"时断言抛错。

### M3【中】`power_cycle()` 没有 `try/finally`

```python
# dh1766.py:465-503（结构）
self._check_mode(expect_mode)
records = []
for i in range(1, n + 1):
    self.set_output(ch, False, expect_mode)   # ← 关断
    time.sleep(off_delay_s)
    self.set_output(ch, True, expect_mode)    # ← 再开
    ...
return {...}                                   # 中途任何异常 → 不返回、不恢复
```
若 `measure_voltage_all()`（第 495 行）或第二次 `set_output` 抛异常（通信抖动、
`KeyboardInterrupt`），本轮循环就停在**断电态**，被测板失去供电，且调用方拿不到
`records/after` 汇总。AGENTS.md 要求"测试脚本必须 try/finally 恢复设定并关闭输出"，
这条同样适用于库内的高层时序函数。

**建议补丁**：把循环体包进 `try/finally`，`finally` 里记录并（按需）恢复最后一次
已知状态，异常时把已完成的 `records` 附在异常信息里：
```python
try:
    for i in ...:
        ...
except BaseException:
    self._last_partial = {"records": records, "state": self.get_output_state()}
    raise
```
**验收**：离线用 fake client 在第二轮注入异常，断言"异常抛出 + 状态被读取/恢复 + records 可查"。

### M4【中】8 条 `STAT:*` 命令在仓内参照物里查无完整出处

本轮修好的命令审计器（`TEST_SCRIPTS/common/audit_all_commands.py`，判据见 §六）对
DH1766 的结论是 **40 HIT / 8 MISS**，MISS 全部是状态寄存器组：

```
STAT:PRES / STAT:QUES? / STAT:QUES:ENAB / STAT:QUES:COND? /
STAT:OPER? / STAT:OPER:ENAB / STAT:OPER:COND? / STAT:QUES:INST:ISUM{n}:{node}?
（dh1766_control/src/dh1766_control/commands.py:41-48）
```
核对参照物：`docs/SCPI_COMMANDS_DH1766A.md` 共 66 行表格、**没有任何 STAT 行**
（只有两处 `SYST:COMM:RLST:STAT?` 的说明文字）；`docs/DH1766 …用户手册.md` 提取版把
4.2.x 各节压成了整段文本（STAT/QUES 仅 5 处零散出现），无法作为逐条出处。
出处实际上是**原版手册 §4.2 状态指令集**，并且这些命令在 2026-08-17 的本机验证里
包含在"40/40 指令读写通过"内（`docs/TEST_RECORDS.md`，留痕 `TEST_DATA/dh1766/dh1766_full_*.json`）。

**结论**：这 8 条**不是猜测命令**（有真机留痕），但"仓内可核对"的链条是断的。
**建议**（纯文档工作，可立即做）：
1. 把 8 条 STAT 命令的**原版手册出处（节号 + 手册原文格式）**补进 `SCPI_COMMANDS_DH1766A.md`；
2. 在审计器基线的注释里登记这 8 条为"已知 MISS（出处=原版手册，真机已验证）"——
   本轮已登记在 `TEST_SCRIPTS/common/verify_audit_extractor.py` 的 `MISS_BASELINE["dh1766"]`；
3. 若日后重排版手册提取（read-pdf 再跑一次并保留 4.2.x 节内命令行），这 8 条会自动转为 HIT。

### L1【低】`init_immediate(None)` 静默无操作

```python
# dh1766.py:222-227
def init_immediate(self, state: Optional[str] = None) -> None:
    if state is None:
        return                      # ← 与全库 "None=查询" 的约定相反（其他方法 None 会回读）
    self.client.write(f"{C.INIT} {state}")
```
调用方 `ps.init_immediate()` 得到 `None`，与"写成功"无法区分（返回类型也标注为 `None`）。
**建议**：要么 `INIT?` 查询并返回当前值（推荐，与 `voltage_mode()` 等一致），
要么改签名去掉默认值，让"不传参"变成 `TypeError`。

### L2【低】类 docstring 对 `safe_mode` 的描述不完整

`dh1766.py:13-15` 写的是"拒绝修改电压/电流设定、OVP/OCP、输出模式（TRAC/SERI/PARA）"，
但实际实现是：
- 单通道 setter 走 `_guard_set`（带电通道拒改）✓；
- **`apply_voltage/apply_current` 完全没守卫**（H1）；
- 输出模式切换走的是"**输出必须全关**"这个**无条件**硬门（`_set_mode_cmd:347`），
  与 `safe_mode` 无关——这是更强的保护，但 docstring 把它挂在了 `safe_mode` 名下，
  读文档的人会以为"safe_mode=False 就可以带电切模式"。
**建议**：改正 docstring，把两套机制的边界写清楚（改完正好覆盖 H1）。

## 四、修复顺序（等仪器回来时按此顺序做）

| 顺序 | 项 | 为什么这个顺序 |
|---|---|---|
| 1 | **H2 `rst()` 加 confirm 门** | 零风险、纯代码、离线可验；先堵住"一句话清设定" |
| 2 | **M1 清理 remote/rwlock 暴露 + 脚本直呼点** | 同样零风险，且它影响后面所有真机测试（测试脚本自己会锁面板就麻烦了） |
| 3 | **H1 `apply_*` 补 `_guard_set`** | 真机验证需要"带电通道"场景，正好用现场 TRAC ±12 V 那台；先离线写桩测试 |
| 4 | **M2 `set_output` 补回读 + 查错** | 会改变调用方可见行为（原本静默失败现在抛错），需要一次完整回归 |
| 5 | **M3 `power_cycle` 加 try/finally** | 同上，且要构造异常注入 |
