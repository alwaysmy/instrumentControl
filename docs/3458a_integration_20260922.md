## 一、为什么必须"专用"

3458A **不是标准 SCPI 仪表**，套用本仓既有的 `VisaClient` 假设会全线失败：

| 用途 | 3458A | 标准 SCPI（34465A） | 本仓既有代码 |
|---|---|---|---|
| 身份 | `ID?` | `*IDN?` | `VisaClient` 的 `query("*IDN?")` 无响应 |
| 错误 | `ERRSTR?` | `:SYST:ERR?` | 错误队列读不到 |
| 复位 | `RESET` | `*RST` | 通用护栏里 `*RST` 是黑名单 |
| 单次读数 | `TARM SGL,1`（触发后**直接回值**，命令不带问号） | `:MEAS:VOLT:DC?` | `instr_query` 要求"每段都是查询单元（以 `?` 结尾）" |
| 档位/积分 | `DCV <range>` / `NPLC <n>` | `:CONF:` / `:SENS:` | 语法不同 |
| 档位回读 | **没有** | `:CONF?` | — |
| 串尾 | **必须 LF**（CRLF 不应答） | 因设备而异 | — |

结论：**不能**用 `instr_query` / `instr_write` 通用护栏操作它（那两条面向 SCPI，且查询判据
会直接拒掉 `TARM SGL,1`）。本库自带命令白名单，见 `keysight_3458a/docs/COMMANDS_3458A.md`。

## 三、设计说明（关键决策与理由）

### 3.1 分层

```
MCP 工具 (ks3458a_*)              server.py：_call/_verify_idn/_remember 一套不变
    ↓
DMM3458A                        dmm3458a.py：配方与语义（丢首读数/恢复/突发解析）
    ↓
Transport 接口                  transport.py：open/close/write/read/read_bytes/query/
    ├─ PyVisaTransport                   clear/drain/set_timeout/ifc
    └─ SiclTransport
```

驱动只依赖**接口**，不直接碰 pyvisa/ctypes —— 所以离线测试能注入假传输覆盖全部配方逻辑。

### 3.2 三条被固化的现场经验

1. **会话恢复的顺序不能改**：IFC/clear → 有限 drain → `TARM HOLD`/`TRIG HOLD`。
   被留在 free-run 的 3458A 会持续吐读数、不理查询，**先 drain 会一直读到数据**
   （参考实现实测 91 s）。`drain()` 硬上限 ≤6 轮 × ≤250 ms（无界 drain 实测 80~91 s，[SICL] L223-230）。
2. **换档/换配置后丢弃第一次读数**：首读数含建立时间与自校准（[SICL] L339-341）。
   `configure_dcv()` / `set_range()` / `configure_acv()` 内部自动丢一次；`set_nplc()` **不丢**
   （参考实现同样如此，NPLC 变化不引起换档建立过程）。
3. **LF 终止符**：pyvisa 默认 `\r\n` 会让 3458A 不应答（[VISA] L529-531 实测超时）。
   `PyVisaTransport.open()` 强制两侧 `"\n"`；SICL 侧 `write()` 自动补 LF。

### 3.3 `reset_on_open=False`（MCP 默认）

参考实现 `DMM3458A_SICL.__init__` 默认 `reset_on_open=True`（校准场景要确定性初态）。
MCP 是**无状态工具**，每次调用连接→操作→关闭，若沿用 `True` 就会"读一个数先把表复位一次"
——既慢又破坏现场。因此本库：

- `DMM3458A.__init__(..., reset_on_open=False)`；
- `server._ks3458a()` 显式传 `False`；
- 重置只走 `ks3458a_reset(confirm=True)`（唯一入口）。

### 3.4 二进制突发：SICL 通路的一处必要修改

参考实现的 `SiclGpib.read_raw()` 把字节 `decode('ascii','replace')` 后返回文本。
这对文本命令没问题，但 SINT 读数的字节里 >0x7F 极常见——`errors='replace'` 会把它们替换成
`U+FFFD`，**整个突发数组变成垃圾**（而且是"看起来像数值"的垃圾）。

本库的 SICL 通路改成：`read_raw()` 返回 **bytes**，只有文本路径才 decode；`read_bytes()`
循环拼包并自己剥 `#<位数><长度>` TMC 头（`iread` 不做块分帧，pyvisa 那边由 `read_bytes` 代劳）。

### 3.5 身份校验沿用同一套

`server._verify_idn("ks3458a", res, d.idn())`：地址可能被 DHCP/重新布线换给别的设备，
连接后必须核对身份。3458A 没有 `*IDN?`，用 `ID?`，返回形如 `HP3458A`，`DEVICE_KINDS["ks3458a"]`
的匹配串是 `3458`。**不通过就拒绝操作**，与其它设备同口径。

### 3.6 不写死地址

`find_3458a()` 的候选顺序（`candidate_resources()`，纯函数、可离线断言）：

```
① 显式 resource
② 解析层已知地址（INSTRUMENT_KS3458A_RES / devices.json / 上次成功缓存）
   —— 远端 VISA server 串（visa://<host>/GPIB0::9::INSTR）通常从这里来
③ hosts 参数里的每个 host → visa://<host>/GPIB0::<addr>::INSTR
④ 本机 GPIB0::<addr>::INSTR
⑤ 本机 sicl:gpib0,<addr>
```

每个候选都真连一次、用 `ID?` 核对，成功即回写缓存并返回 `{resource, idn, transport, tried}`
（`tried` 保留失败原因，便于回答"为什么最后选了这条通路"）。**不做网段扫描**——3458A 在 GPIB
总线上，不是 LAN 设备；`allow_scan=True` 也只扫"本机 VISA 已注册的 GPIB 资源"。

### 3.7 解析层的一处最小改动

`is_visa_resource()` 原本只认含 `::` 的串。`sicl:gpib0,9` 不含 `::`，会被当成**裸主机名**
拿去做 LAN 协议探测（对 `sicl:gpib0,9` 发 `*IDN?` 既无意义又危险）。现改为：

```python
if text.strip().lower().startswith("sicl:"):
    return True
return "::" in text
```

其余解析链（优先级、缓存、canonicalize、自动发现）**行为不变**。

## 五、两条通路怎么启用

3458A 挂 GPIB，本机/远端两种接法：

### ① 远端 VISA server

```powershell
python mcp_instruments/config_cli.py set ks3458a "visa://<host>/GPIB0::9::INSTR"
# 或临时：$env:INSTRUMENT_KS3458A_RES = "visa://<host>/GPIB0::9::INSTR"
```

### ② 本机 Keysight SICL（本机 VISA 打不开 GPIB 卡时）

```powershell
python mcp_instruments/config_cli.py set ks3458a "sicl:gpib0,9"
```

前置条件：装了 Keysight IO Libraries Suite（`sicl32.dll` 可加载；库会在
`Program Files\Keysight\IO Libraries Suite\bin` 等目录里 `add_dll_directory`）。
**不要**在配置里写裸 IP——`sicl:` 与 `GPIB0::…` 都是"完整资源串"，直接填。

不配置也能用：`ks3458a_*` 工具会按 `本机 GPIB0::9::INSTR → sicl:gpib0,9` 依次探测
（`find_3458a()`），失败才报错并给出三条可执行指引。

### SICL 什么时候必须用

- 本机用 82357B 等 USB/GPIB 卡，且 **Keysight VISA 打不开** `GPIB0::<addr>::INSTR`
  （报 `VI_ERROR_INTF_NUM_NCONFIG`；`GPIB0::INTFC` 能开说明总线是通的）—— EmoeCalibrator 现场即是；
- 需要发 **IFC（接口清除）**：VISA 侧没有等价物，`PyVisaTransport.ifc()` 只能退化成 Device Clear，
  遇到"表被留在 free-run、Device Clear 也停不下来"时，IFC 是更硬的手段。

## 九、仍未验证 / 待手册核对（汇总）

完整 13 条见 `keysight_3458a/docs/COMMANDS_3458A.md` 的「待手册核对项」。要点：

1. **`TEMP?`**：单位、是否需要选件、返回格式全部未验证（任务书命令，参考实现里没有）；
2. **`ACV` / `SETACV` / `ACBAND`**：整组未验证（同上）；AC 下的 `NPLC` 语义也未核对；
3. **`ERRSTR?` 队列语义**：是否每次弹一条、深度、如何清空（白名单没有清空命令）；
4. **`RESET` 的完整影响范围**：只按参考实现补了 `END ALWAYS` + `INBUF ON`，复位面未逐项核对；
5. **突发尾部 2 字节**：样例固定读 `2n+2`，多出的 2 字节含义未核对（本库只取前 `2n`）；
