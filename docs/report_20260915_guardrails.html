一、护栏拦截了什么

三道口子：写路径（instr_write 与各设备写工具）、查询路径（instr_query/dg_query）、 设备类高危动作（输出/关机/复位/复位兜底）。下面按"拦什么 / 怎么判 / 证据"列。

1.1 命令黑名单（命中即 error_type=forbidden，confirm 也不放行）

家族拦截写法（含短/长/中间缩写）为什么拦处置策略
复位 *RST、:SYSTem:RESet、:SYST:RESE、:SYST:PRESet、:SYST:FACTory 清空现场全部设定（别人调好的通道/触发一起没） 零暴露；常量保留 + 语义说明 + 受控脚本
存储覆写 *SAV n、*RCL n 覆写/调用仪器存储位，等同改设定且难追溯 一律拦
远程锁定 SYST:REM ON、SYST:RWL、:SYSTem:LOCKed ON、:SYST:COMM:RLST RWL 禁触摸屏/面板按键，现场无法人工接管 写拦、纯查询放行（SYST:REM? 等留作诊断）
参数偷发 :MEASure:ITEM? VPP,*RST、:OUTP1 ON;:OUTP1? 把写命令塞进查询消息的参数位或 ; 后续段 逐 ; 分段判 + 公共命令族整段搜索
判据 助记符前缀匹配（short..long 任意前缀）+ 逐段判定—— 避免 SYST:RESE 这类合法中间缩写漏网（SCPI-99 §6.2.2）。

1.2 查询判据（修过一次的坑）

形态判定说明
*IDN?、:SYSTem:ERRor?放行无参数查询
:MEASure:ITEM? VPP,CHANnel1
SAMPle:COUNt? MAX		 放行 问号后允许带参数——两系列 RIGOL 手册的实例都是这个形态。早期误按"整段以 ? 结尾"判， 把这类合法查询一并拒了（用户报障后修正）
*IDN?;:SYSTem:ERRor?
:OUTP1?;:OUTP2?		 拦截 多单元消息一律拒（查询口一次只收一条命令，拆分调用即可）。依据：SCPI 里 ; 分隔的是 同一条消息内的多个命令单元，设备逐个执行——Keysight 手册明文（TRIG:SOUR EXT;COUNT 10 等价于两条命令），DG832 实测 :SOUR1:PHAS?;:SOUR1:PHAS 123 的写单元真的生效
*IDN?;*RST、:SYSTem:LOCKed ON;*IDN? 拦截多段消息里夹带写命令
:DISP:TEXT "why?" 拦截 写命令的参数里恰好含 ?：因引号不构成助记符，仍判为写

1.3 状态声明门 & confirm 门（高危动作先验后动）

工具门语义
sdg_output / dg_outputconfirmexpect_load 开/关都要授权；负载声明（HZ/50Ω）仅校验不设置，不符即拒
psu_output / psu_power_cycleconfirmexpect_mode 拓扑声明（NORM/TRAC/SERI/PARA）；防 TRAC 联动下误操作
sds_shutdown / mho_autosetconfirm 关机需手动开机；autoset 是全局破坏性（重置所有通道/时基/触发）
usb_reset（故障兜底）confirmescalate 重启该仪器的 USB 节点（会话中断 2~3s）；无管理员权限时需显式提权（弹 UAC）

1.4 库内联锁（不靠调用方自觉）

  • DG832 防超压联锁：设幅度/偏移或开输出前必须已开有效电压保护，否则 protect_required；越界 protect_range——不静默超压。
  • DH1766 继电器保护：切换输出模式（TRAC/SERI/PARA）前必须输出全关，库内无条件拦截。
  • DH1766 safe_mode：带电通道拒绝改设定（已知可被 apply_voltage() 旁路， 已列专项审计待修，见 docs/dh1766_audit_20260915.md）。
  • 复位族"保留但不暴露"：命令常量留在各库 commands.py（附语义与风险）， 库内无公开方法、MCP 无工具；万一要用走受控脚本 rigol_scope_reset.py --allow-reset --reboot|--factory。

1.5 兜底与留痕

  • 看门狗：离线/挂起资源硬超时（≥30s），不让 MCP 被一条死连接冻住； 超时在审计里记 executed="unknown"（命令可能已送达，需回读确认）。
  • 审计落盘：每次通用写（含被拒绝的）→ TEST_DATA/common/mcp_scpi_audit_*.jsonl。
  • 地址自证：连接后核对 *IDN?，地址被 DHCP 分给别的设备时直接拒绝下发 SCPI。
